# 实验方案：两种融合方式的对照（通用版）

状态：提议，待评审

本方案回答一个问题：把外部 8 个分析器接进 sleuth，哪种做法真的提升诊断质量——**沉淀成知识**（reference 词条），还是**接成能力**（diagnose 里能调工具）。不预设结论；基线是现在 main 上的 sleuth。

## 1. 三条实验臂

| 臂 | 分支 | 相对基线的唯一差异 |
|---|---|---|
| 基线 | `main`（不动） | 无 |
| 臂 A：知识融合 | `kb/absorb-analyzers-refs` | 多出若干 reference 词条（方法论、阈值、工具事实），诊断流程与工具不变 |
| 臂 B：能力融合 | `kb/analyzers-plugin` | 多出一个分析器工具与转接文档，知识库不变 |

**只允许一处差异**。臂 A 不许顺手改流程，臂 B 不许顺手加词条；否则结果无法归因。

## 2. 语料

- 规模：起步 20 题；三臂同题、同材料、同顺序。
- 构成：按性质分层——中断 / 精度 / 性能各约三分之一；负载类型训练与推理都要有。每层至少 5 题，避免某一臂靠单类题拉开差距。
- 材料：每题只给工程师当时能拿到的东西（日志片段、prof 路径、dump 路径、报错原文），不给答案。
- 已知答案：每题先写清根因与正确处置，作为判定依据，实验前封存。没有已知答案的题不进语料。

## 3. agent 要做什么

对每一题：

1. 新开一个会话，只发题干与材料，用 `/diagnose`；
2. 只按流程走，不额外提示（必要的澄清提问由 agent 自己发起）；
3. 走完必须产出：结论（根因）、置信度、fix 建议、以及本次用到的证据与知识来源。

同一题在同一臂里只跑一次；只有判定为"证据不足、无法判定"的题才允许重跑一次，并记录原因。

## 4. 产出与记录

每题一份 trace（`traces/<session>.yaml`）加一份定位报告（`traces/<session>.report.md`）。三臂用同一套 trace 字段，不新增字段，避免记录差异被当成效果差异。

实验人员在题外另记一张表，每题一行：

| 字段 | 取值 |
|---|---|
| 题号 / 性质 / 负载类型 | 固定 |
| 臂 | main / A / B |
| 是否命中根因 | 命中 / 部分 / 未中 |
| 首轮是否问到关键事实 | 是 / 否（关键事实在答案里预先列出） |
| 是否给出可执行 fix | 是 / 否 / 只给了排查方向 |
| 是否使用了新增内容 | 是（列 ref-id 或工具调用）/ 否 |
| 耗时、trace 字数 | 现算 |
| 误诊代价 | 给了错误 fix 且被采纳 / 无 |

## 5. 怎么对比

主指标一条：**根因命中率**（命中记 1，部分记 0.5，未中记 0）。三个臂各算一个数，报绝对值与差值。

辅助指标：首轮关键事实命中率、可执行 fix 比例、平均耗时、trace 字数、误诊代价次数。

判读规则，实验前定死：

- 臂 A 的命中率比基线高出不足 10 个百分点 → 视为"知识融合无效"，不动知识库；
- 臂 B 的命中率不高于臂 A，且平均耗时或上下文成本更高 → 视为"能力融合不划算"，不推进插件；
- 某一题三臂全错 → 记进"语料或知识缺口"，不进任何一臂的分子。

**盲评**：判定命中的那个人不看臂标签，只看题目与三份产出（顺序打乱）。

## 6. 已知偏差与应对

- 题目若集中在 prof 与工具类，臂 B 天然占优；集中在版本与阈值类，臂 A 天然占优。分层抽样就是为了压这一条。
- 命中判定是主观的。一个人判、另一个人抽 20% 复核，不一致的题讨论到一致。
- 单次运行有随机性。关键题（三臂结论不一致的）各补跑两次，报三次结果，不取最好的一次。
- 材料不足会让三臂全错，看起来"都没用"。判据里已有"全错进缺口"的处理。

## 7. 预算

20 题 × 3 臂 = 60 次诊断。按每题 15 分钟粗估，约 15 小时；人工判定与复核另计 3–4 小时。先跑 6 题做预演，确认题干与判定口径能对齐，再补满 20 题。

## 8. 本分支的角色

见提交本文件的分支：`kb/absorb-analyzers-refs` 为臂 A，`kb/analyzers-plugin` 为臂 B。两臂共用本文件，各自只补一节说明本分支相对基线改了什么、验收时看哪些产物。
