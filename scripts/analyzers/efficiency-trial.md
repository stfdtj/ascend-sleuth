# 在工作机上测分析器能省多少诊断操作

状态：提议

在诊断质量达到同一要求的情况下，启用仓库内置分析器能否减少模型的取证操作？上一轮的 10 分表已经能评诊断报告。新一轮用会话记录补测工具调用次数、补证轮数、有效耗时和工具返回文本量。[上一轮实验方案](model-trials.md)

## 做完得到什么

每题得到 A、B、C 三份独立报告、原有质量分、四项原始读数和两组逐题差值。**B → C 是主对照**，测相同判读提示下添加分析器的收益和代价。A → B 测直接提供判读提示的效果。

6 个分析器各准备一题材料充分、一题材料有缺口或不可比。全量共 12 题、36 次诊断。先做 iBMC 两题的 6 次诊断，确认工具调用和耗时能从记录复算，再按分析器逐批完成。

## 准备材料

在可访问原始日志的工作机准备 Python、PyYAML 和能导出完整工具调用记录的诊断会话。每题留三份材料副本，并把题干、评审答案和可补材料分开。先选独立的新案例。复用历史输入时，隔离旧报告和答案，用新会话重跑。

| 分析器 | 材料充分 | 材料有缺口或不可比 | B、C 共用的判读提示 |
|---|---|---|---|
| `ibmc_analyzer` | 完整收集包，能核对告警时间、设备位置和读数 | 有电源事件，缺 NPU 在位证据 | 按设备和时间关联事件、在位与计数。缺一类证据时，把对应硬件状态记为未知。 |
| `issue-analyzer` | 中断日志，含失败 rank 和框架栈，能与宿主机或设备日志对齐 | 缺失败 rank 或跨机时间对应关系 | 按主机、rank 和时间窗核对首个能解释故障的事件。回原文核对重复报错是否来自同一事件。 |
| `ascend-dump-analyzer` | 两份环境快照 JSON，已知变更，能核对关键字段两端原值 | 两份可读快照，至少一端缺关键字段 | 逐项核对版本、配置和环境变量。缺字段记未知。用复测或变更记录验证差异是否与故障有关。 |
| `cluster-analysis` | 一份多卡 Prof 采集或已有集群结果，带 rank 和 Step 范围 | 部分 rank 或目标 Step 缺失，仍能确认预期覆盖 | 先核对实际与预期的 rank 和 Step。用同一时间窗的计算、通信和等待证据解释慢 rank。 |
| `cluster-compare` | 两份集群结果，基准端和对比端负载、rank 映射和 Step 可对齐 | 两份结果可读，但缺共同 Step 或 rank 映射 | 先核对负载、rank 和采集窗。只对可对齐的观察项计算阶段差值。 |
| `cpu-host-performance` | 一份 Host trace，含线程身份和同时间窗的 NPU 侧证据 | 只有 Host 侧现象，缺 NPU 对照或线程身份 | 把 Host 调度或资源现象定位到线程和时间段。用同一时间窗的 NPU 证据验证影响。 |

组织者提前写每题的必需证据、可接受结论或未知范围、会导致误判的说法，以及可回答的补证内容。三组初始材料及后续可给事实相同。现实中取不到的材料统一回复暂无。模拟缺项只改实验副本，并记录删减。

## 步骤

1. **冻结组别与版本。** 所有诊断克隆固定在 `da23174e6ec1f4488ffe1d68131a774076e0b882`，共用模型及版本、推理设置、命令预算、返回限制和相同的诊断要求。三组都可以读材料、搜索和运行通用 Python。共用的参考资料在派发前固定范围，排除本轮分析器说明和新增判读资料。

   | 组 | 当题判读提示 | 内置分析器 |
   |---|---|---|
   | A | 无 | `SLEUTH_ANALYZERS=off`，跳过分析器步骤 |
   | B | 上表对应一行 | `SLEUTH_ANALYZERS=off`，跳过分析器步骤 |
   | C | 与 B 逐字相同 | `SLEUTH_ANALYZERS=on`，按当前诊断流程选择，可查工具用法 |

   派发时要求 A、B 跳过 `scripts/analyzers/` 与分析器分派手册，包括说明、适配器和上游脚本。检查会话记录时，发现 A、B 读取这些内容或直接运行上游脚本，按串组处理。

   组织者在 C 的环境中执行 `python scripts/analyzers/cli.py status --json`，确认 `enabled` 为 `true` 且当题分析器的 `installed` 为 `true`。用另一份样例验收工具能输出结果，再用一次排练验证能记录全部工具动作、返回正文和时间。预检和排练在正式计时前完成。[分析器调用说明](README.md)

2. **每题用三个新会话。** 参照分支首页准备独立克隆和输出目录。一个组织者可一次安排两题共 6 个独立子代理。每个子代理只收到当组条目、题干、材料路径和统一的报告要求。从空白上下文开始，跳过既有案例、复盘、旧 trace、评审答案与其他组结果。三组使用各自的输入副本，多卡 Prof 工作副本允许当前流程写 `cluster_analysis_output/`。[独立克隆与派发步骤](../../README.md#在工作机上跑-ibmc-诊断对照)

   同一工作机一次只运行一个正式计时会话。开跑前按题号固定轮换顺序，例如依次用 ABC、BCA、CAB。C 自行决定是否调用及何时回查原始证据。记录未调用、选错、失败、超时、部分成功及回退。补证按预先写好的答复提供。

3. **收报告和会话记录。** 统一的诊断窗口从模型收到题干开始，止于提交本次最终诊断。每次证据操作记录时间、调用对象、结果、实际返回给模型的正文。补证另记请求、答复时间和新增材料。诊断 trace 和分析器产物用于核对操作与证据位置。

## 怎么确认做对了

### 原诊断质量分（10 分）

两名评审在隐藏组名和效率数据后独立评分。原五项各 0–2 分，保留两人的分项和分歧。0 分表示错误或漏答，1 分表示方向合理但证据或动作不清，2 分表示判断与证据吻合或行动具体且适用。[原评分口径](../../README.md#怎么确认做对了)

| 质量项 | 评审看什么 |
|---|---|
| 结论 | 根因或已证实的边界是否与材料一致 |
| 证据 | 能否回到原始位置核对支撑结论的值、单位和范围 |
| 观察项处理 | 是否区分已证实故障、候选解释和附带现象 |
| 缺证据处理 | 是否说明未知项及其对判断的限制 |
| 补证 | 是否提出能改变下一步判断的最少材料或动作 |

两组达到事前写好的同题验收条件后，该配对才进入效率计分。验收看必需证据、可接受的结论边界和预先列出的误判。评审有分歧时，先回原文核对，再判是否可比。报告质量下降、证据遗漏及未达到验收条件的配对单列，保留原始读数。

### 新增效率评分（四项各 0–2 分）

分别用 A 作为 A → B 的基准、B 作为 B → C 的基准。四项分开报告，每项分数旁都给原始差值。诊断窗口中的选工具、失败、重试和回退同样计数。

| 指标 | 怎么测 | 2 分 | 1 分 | 0 分 |
|---|---|---|---|---|
| 模型发起的取证工具调用 | 按会话记录中的工具请求逐条计读、搜、通用脚本、分析器 `status`、`list`、`run` 和读回产物。并行批次计各个实际请求；一次 shell 请求算一次，记录其中是否合并了多个取证命令。 | 少至少 1 次 | 相同 | 多至少 1 次 |
| 补证轮数 | 模型向组织者发出一次补证请求记 1 轮，同一条消息中的多项请求算同一轮。记录是否得到材料及新增材料种类。 | 少至少 1 轮 | 相同 | 多至少 1 轮 |
| 有效诊断耗时 | 诊断窗口的总耗时减仅等待组织者答复的时间。模型推理、工具运行、超时和重试都计入。有工具并行时按墙钟时间计。 | 少至少 `max(30 秒, 基准 × 10%)` | 差值绝对值低于该阈值 | 多至少该阈值 |
| 工具返回文本量 | 对实际进入模型的工具响应正文计 UTF-8 字节，含错误和重复读取。以截断后的正文为准。产物只写到磁盘时，等模型读到时再计。 | 少至少 `max(1 字节, 基准 × 10%)` | 差值绝对值低于该阈值 | 多至少该阈值 |

另记诊断窗口内模型发起的工具调用总数、分析器启动次数、已知子进程数及工具状态。写 trace 或最终报告的调用仅进总数。取证调用降低但子进程或耗时上升时，同时报告差值。输入负担单列首轮材料形态、后来要补的材料及是否需要另采或转换。

每次运行的记录包含题号、组别、提交、模型、报告和关键证据、两位评审的分项、四项原始读数以及工具状态。每个指标按分析器汇总改善、持平、变差和无法比较的题数。全量汇总给出有效配对分母和配对差值中位数，并分别查看材料充分题与有缺口的题。每个分析器只有两题，结论注明适用的输入形态和观察到的代价。

## 出错了怎么办

- 工具失败、超时或只读到部分数据时，继续完成诊断并保留回退动作。符合质量条件时，照常计算效率。
- 工具记录或计时缺失时，受影响的指标记「无法比较」。诊断 trace 可辅助核对，单靠它无法证明每一次读、搜和脚本调用都被记下。
- 题干泄露答案、组别交叉读结果或运行条件发生变化时，保留作废记录，给同题三组换新会话和工作副本复跑。

## 怎么结束和清理

报告、诊断 trace、会话记录和评审依据留在工作机的获准目录。确认读数和证据可回查后清理临时副本。对外汇总只用获准公开的结果和脱敏材料。

## 本轮工具范围核对

按固定提交的调用入口、上游保留目录和 5 个新增 Sleuth 词条逐项核对。下表给出当前接线、输入限制和仍可单独评估的部分。[来源清单](PROVENANCE.yaml) [注册表](registry.py) [用法](README.md)

| 上游来源 | 当前调用或保留形态 | 核对结果 |
|---|---|---|
| `ibmc_analyzer` | 自动调用 `run_bmc_report.py`，连同解析和报告脚本 | 依赖 iBMC 收集内容。BMC 告警与传感器两个知识词条可用现场读数复核。工具词条单列输入和产物。 |
| `issue-analyzer` | 自动调用 `log_analyzer.py` 扫描、提取、回验，保留上游说明 | 规则匹配受日志类型、时间窗和错误模式覆盖约束。跨机排序和归因需回原文。 |
| `ascend-dump-analyzer` | 上游目录只保留 `compare_dumps.py` | 至少需要两份可读快照。只提供字段对比。兼容性判断和单份报告路径已去除。 |
| `cluster-analysis` | 自动调用 `run_workflow.py --no-native`，保留本地分析和集群子报告 | Sleuth 入口走本地实现。原生工具分支仍在上游目录。保留同次采集内的双 rank 差异 JSON，工作簿是可选输出。 |
| `cluster-compare` | 读取两份已有集群结果，生成 HTML 和 Markdown。提取时固定 `--no-advanced` | Sleuth 入口跳过依赖 `msprof-analyze` 的进阶分析。上游进阶入口和独立校验脚本仍在保留目录。 |
| `cpu-host-performance` | 离线解析 Host trace。可能生成绑核建议脚本 | 采集和绑核执行不进自动流程。报告的绑核计划会导入 `hostbind` 的规划模块，取舍时要和现场执行入口分开核对。 |
| `prof-compare` | 只保留 Sleuth 的性能基准判读词条 | 已移除独立和内嵌两处上游工具副本。判读可直接使用给定读数，没有工作簿输入要求。 |
| `vllm-ascend-tuning` | 保留上游提示、调优说明和配置模板 | 目录未注册为 CLI，也未转写为本分支新增的 Sleuth 词条。配置仍需核对使用场景和软件版本。 |

本分支新增的三个通用词条是 BMC 告警模式、BMC 阈值使用约束和性能基准对照方法。前两项保留待审核状态，适用性由设备、读数和证据决定。另两个词条说明保留的 iBMC 分析器和通用 CLI，可注明输入文件与产物。上游随附文档属于工具包，其中仍有对应命令和格式说明。
