# 这 8 个 skill 被我们改成了什么（给原作者看）

项目原本的说明在 [main 分支](https://github.com/pillumina/ascend-sleuth)。**本分支是版本 A：只把你的经验写成知识条目。**

## 你的 skill 其实是两半

一半是说明文字，告诉 agent 遇到这类问题该怎么想；另一半是程序，真正去读数据、算数字、出报告。两个版本各取一半：

- **版本 A（本分支）**：只搬说明里的经验，写成 sleuth 的知识条目；程序不进来。
- **版本 B**：把程序装进一个插件，诊断时能启动它们；知识库不动。

## 变成了什么

版本 A 不是插件包，是一批知识条目，一条一个文件写在 `references/` 下。sleuth 诊断时会按需加载它们，用来判断「这类问题该先看什么、什么情况下别下结论」。

版本 B 打成一个插件包，装一次就能在诊断里启动你的程序，8 个程序各占一行开关。

## 还会有什么产出

**版本 A 没有文件产出。** 条目只影响诊断时的判断。sleuth 自己会产一份 Markdown 定位报告，那是它自己的格式，不是你那套 HTML。

**版本 B 报告还在。** 程序照旧把 HTML / Markdown 写到自己的输出目录，sleuth 只拿路径、不读内容——版式、图、结论和你现在的一模一样。每次调用会多留一份 `result.json`（结论摘要、证据位置、缺了哪些数据）和一份调用记录。

## 什么时候会被用到

- agent 按症状路由到某一类问题后，会把相关条目读进来做判断；它不会逐份读你的样例，读的是提炼出来的判断依据。
- 工程师也可以直接问「这类问题一般先查什么」，走的也是这些条目。
- 用不到的情况：材料太少、问题不在这些条目的覆盖范围内、或者条目本身没写清适用范围。

所以条目能不能被用上，取决于它写没写清「什么情况下适用、什么情况下不成立」。

## 怎么开始

准备一个目录，准备完把路径贴过来，再说清这轮要比什么：

```text
trial-input/
├── case-01/
│   ├── question.md      题干
│   └── materials/       脱敏后的材料
├── case-02/...
review-only/
├── answers.md           根因与正确处置，不给诊断对话看
├── supplements/         可选补充事实
└── comparison.md        评审记录
```

答案放在 `review-only/`，不要放进诊断用的工作区。另外每个分析器最好给 2–3 份样例，我们用它来核对条目写得对不对。

## 不会替你做的事

- **不自动装包**：缺 Python 包或 `msprof-analyze` 时，返回「缺什么」和一条命令，装不装由工程师决定。
- **不改机器**：采集、绑核、改系统参数都不在自动调用范围内，只写进建议。

## 怎么比

同一批题，原版 sleuth、版本 A、版本 B 各跑一遍，每题开一个独立对话，只发相同的题干和材料。比三样：根因说对没有、第一轮问对关键事实没有、报告能不能直接拿来用。差异明显的题再各跑一次，结果全部保留。评审时先隐藏版本标签更好。
